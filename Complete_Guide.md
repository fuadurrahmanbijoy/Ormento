# Complete Guide: Writing, Building and Printing an Introductory Business Studies Book

*A complete, self-contained system for turning a course file into a finished book for first-year students with no business background: a dignified Victorian-style A4 volume, written chapter by chapter as tagged text and built into a PDF by a script.*

**The parts**

- **Part I, Master Workflow:** the order of work and who decides what.
- **Part II, Intellectual Guide:** how each idea is taught (voice, structure, length, examples, numbers).
- **Part III, Beginner Guide:** the extra care an absolute beginner needs.
- **Part IV, Visual Guide:** how the book looks.
- **Part V, Token-Saving Guide:** how chapters are written and built (tagged text, session limits, build instructions).
- **Part VI, Planning Guide:** how a course file becomes a chapter blueprint.
- **Appendix A:** the build script.

**Which parts to load**

- **Planning chats:** Parts I and VI, with Parts II and III for chapter shape.
- **Drafting chats:** Part V (it holds the style card), the state file, and the chapter's blueprint entry. Open Parts II and III only when a rule needs checking.
- **Build chats:** Part V, Appendix A, the fonts, and the tagged chapters.

References such as "Intellectual Guide, section 5" mean section 5 of Part II, and so on. The only item outside this file is the set of font files named in Part V.

## Part I: Master Workflow Guide

*How the guides fit together, who decides what, and the order of work. Read this first; it tells you when to open each of the other guides.*

---

### 1. The Set of Documents

| Document | It answers | Used when |
| --- | --- | --- |
| **Planning Guide** (Part VI) | *What* goes in the book, and in what order | Planning: turning the course file into chapters, sections, example plans, and practice plans |
| **Intellectual Guide** | *How* to teach each idea (voice, spine, length, examples, numbers, referencing, chapter shape) | Writing every chapter |
| **Beginner Guide** | *How much extra care* an absolute beginner needs (language, definitions, pace, sequencing) | Writing every chapter, layered on top of the Intellectual Guide |
| **Visual Guide** | *How the book looks* (page, type, headings, side column, cover, print) | Laying out and proofing; also shapes how text is written (side notes, footnotes) |
| **Test chapter** | One chapter built with the script (Part V) to show the Visual Guide in use | Whenever the layout needs checking |
| **Token-Saving Guide** (Part V) | *How chapters are written and built* (tagged text, session limits, state file, build script) | Every drafting and build chat |
| **This guide** | The order of work and the rules for conflicts | Always |

**The course file** (objectives, topics, past questions) is **private input**. It is used only in planning and checking, and it never appears in the book.

---

### 2. Who Decides What

When guides seem to disagree, use this order.

1. **The Planning Guide (Part VI) decides the content and order.** What is covered, how topics are grouped, where examples and practice go.
2. **Intellectual Guide decides the method of teaching.** Structure of a concept, register, length tiers, chapter shape.
3. **Beginner Guide adjusts pace and language.** Where it asks for shorter sentences, slower pace, or simpler definitions, it overrides the Intellectual Guide for that passage.
4. **Visual Guide decides presentation.** Writing must fit what the page can carry (for instance, every paragraph should be summarisable in one line for the side column).
5. **Token-Saving Guide decides the output format and session limits.** Chapters are written as tagged text, one chapter per chat, with no layout code. It never changes content, voice or level.
6. **The author decides anything left open**, and the answer is recorded in the decision log (section 6).

**Two standing rules that override everything**

- The back story (objectives, topics, past questions, marks, frequency) never appears in the book.
- Question frequency and marks never change how large or emphasised a topic is. They affect only examples and end-of-chapter practice.

---

### 3. Adapting to the Type of Course

The Intellectual Guide's rules for calculations apply **where a course has calculations**. For a descriptive course (such as one on the nature of business, forms of ownership, trade, and institutions):

- Replace "worked example" with a **worked case**: Situation, Question, Reasoning, Conclusion, Check. It applies an idea to a situation; it is not a model exam answer.
- Replace the change-the-numbers ladder with a change-the-**situation** ladder: the same idea in a familiar case, then a reshaped case, then a new setting, then a case that combines earlier ideas.
- Present distinctions (for example, between two forms of organisation) in a short **comparison table**, introduced in words first.
- Use the running business and verified historical cases as the source of scenarios.

The book never includes model exam answers or a guide on writing them. Its job is to build understanding complete enough that a reader can answer.

---

### 4. The Workflow, Stage by Stage

#### Stage 0: Set up once

1. Choose the book title, spelling convention (British or American), default country, currency, and date format.
2. Decide the running business (type and starting facts).
3. Open the working files (section 6).
4. Fix the layout by building one test chapter with the build script (Part V) and checking it against the Visual Guide.

#### Stage 1: Inventory the course file

Follow **Part VI, steps 1-4**: list objectives, topics, and questions; flatten topics; profile the questions; map questions to topics; log unmapped questions and topics with no questions.

#### Stage 2: Analyse

Follow **steps 5-6**: break topics into concepts, draw the dependency map, and decide what foundation material a beginner needs first.

#### Stage 3: Blueprint

Follow **steps 7-9**: form chapters and sections by teaching logic, order by dependency, handle overlaps, and fill in one blueprint entry per chapter.

> **Checkpoint 1.** The author reviews the blueprint before any drafting begins: chapter list, order, sections, and foundation material.

#### Stage 4: Prepare each chapter

For the chapter about to be written:

1. Read its blueprint entry.
2. Extend the case file with this chapter's step in the running business, carrying forward all earlier figures.
3. Choose and verify the historical case.
4. Plan the example ladder and the end-of-chapter practice (**step 10**).
5. Add the chapter's new terms to the term bank.

#### Stage 5: Draft the chapter

Write in tagged text (Part V) in this order:

1. **The opening puzzle** (half to one page).
2. **The sections.** For each concept:
   - Choose the approach by kind of topic (Intellectual Guide, section 3).
   - Follow the layered spine: idea, example, rule, exceptions.
   - Choose the tier for length by importance, not frequency; three lines is the minimum.
   - Apply the Beginner Guide: short sentences for new material, every term defined in simple English in bold at first use, standard or slow pace as the idea demands.
   - Write the side-column line for each paragraph, and key-term notes where a term appears.
3. **The worked case** from the running business.
4. **The closing pack**, in order: summary, think it through, where people go wrong, in history, sources only for defining topics.
5. **The end-of-chapter practice** from the plan.

#### Stage 6: Check the chapter

Run all of these before calling a chapter done:

- Intellectual Guide checklist (section 10).
- Beginner Guide checklist (section 10).
- **Silent coverage check** (Part VI, step 11): every past question tied to this chapter is answerable from it.
- **Clean-out scan** (step 8): no objective labels, exam years, marks, frequency remarks, or copied questions.
- **Fact check:** every date, name, figure, and legal point verified against a reliable source.
- **Continuity check:** terms, case-file figures, and cross-references agree with the working files.

> **Checkpoint 2.** After the first chapter is finished, the author reviews it fully and confirms that the voice, pace, and level are right. Adjustments are made to the guides themselves before writing the rest.

#### Stage 7: Assemble

Write front matter ("To the Reader" note, preface, contents) and back matter (glossary from the term bank, further reading, index). Collect review questions in their place.

#### Stage 8: Lay out and proof

1. Run the build script (Part V) on the tagged chapters and check the pages against the Visual Guide.
2. Print a **dummy** of 8-16 pages on the intended paper.
3. Test-read with a few real beginners and note where they slow down or get lost.
4. Correct the text and the guides.

#### Stage 9: Final pass and print

Repeat the coverage check and the clean-out scan on the whole book. Order a proof from the printer before the print run.

Begin with the opener tags and the opening puzzle. Finish with the closing pack and the practice set. End as Part V, section 5 requires.

The assistant's short closing list feeds the state file, so nothing is lost between sessions.

## Part II: Intellectual Guide

*Reference for content, tone, depth, and structure. Field: Business, Management, Accounting, Micro-economics, Finance. Audience: first-year university students.*

---

### 1. The Approach in One Paragraph

Each idea is taught in **layers**: the idea, then an example, then the rule, then the exceptions. Topics usually open with a **puzzle or question**. Explanations are never hurried, and length depends on importance, with a floor of three visible lines. Examples come from two tracks: a **documented running business** and **real historical cases**. Every calculation is worked by hand, step by step, because students will sit exams. Referencing is light by default and moderate for defining topics. Every chapter closes with the same set of features.

---

### 2. Voice: One Book, Four Registers

The book has one consistent character: serious, clear, and never condescending. The register shifts with the job being done.

| Register | Use it when | How it sounds |
| --- | --- | --- |
| **Storyteller** | Introducing a new, complex idea | Opens with a puzzle or a moment of tension; builds the idea so the reader wants the answer |
| **Plain authority** | Stating definitions, rules, and principles | Short, exact sentences; no ornament |
| **Patient tutor** | Worked examples and procedures | "We" and "you"; each step announced and explained |
| **Measured professor** | Framing, history, and judgement | Dignified, slightly formal, suited to the Victorian look of the book |

**Language rules**

- Average sentence about 18-22 words. Vary it; a short sentence after a long one lands well.
- Define a term before using it. Introduce a term once, in bold, then use it the same way throughout.
- Avoid idioms and slang that may not travel across cultures or languages.
- Write in the active voice unless the actor truly does not matter.
- Never hurry. If a step matters, give it room.
- No jokes at the reader's expense; wit is welcome only when it helps an idea stick.

---

### 3. Which Approach for Which Topic

| Kind of topic | Open with | Then |
| --- | --- | --- |
| **A new, complex idea** (something the learner has never met) | A puzzle or question, told in storyteller mode | Build the idea in layers; end with the plain rule |
| **An existing framework or phenomenon** (market structures, financial statements) | A puzzle, then a concrete example | Draw out the general principle; state the rule; note exceptions |
| **A technique or procedure** (journal entries, break-even, NPV) | A concrete example | Worked example in tutor mode; formula afterward |
| **A defining theory with a known origin** (division of labour, double-entry) | A short historical hook | Explain the idea; connect it to a modern case |

When in doubt, start with a question the reader can almost answer.

---

### 4. Anatomy of a Concept (the Layered Spine)

Most concepts follow this order:

1. **Idea.** What it is, in plain words, and why it matters. Opens with a puzzle where suitable.
2. **Example.** A concrete case, from the running business or from history.
3. **Rule.** The definition, principle, or formula, stated precisely.
4. **Exceptions.** Where it fails, limits, and common confusions.

Weave the other three approaches in briefly, so the understanding is thorough:

- **By questions** (What is it? Why does it exist? How does it work? Where does it fail?). Use these to check that no layer is missing.
- **By viewpoint** (owner, manager, employee, customer). A sentence or short paragraph showing how the idea looks from another seat.
- **By stages** (simple, then detailed, then advanced). Give the simple version first; add detail only after the simple one is secure. Mark advanced material clearly so a beginner can defer it.

---

### 5. How Long Each Piece Should Be

Length follows importance. It should never feel hurried, and it should never feel padded.

| Tier | What it covers | Typical length |
| --- | --- | --- |
| **Minor term** | Vocabulary and small distinctions | 3 to 8 lines (**never fewer than three visible lines**), plus a side note |
| **Standard concept** | Most ideas in a chapter | 150-300 words |
| **Core idea** | The idea the section exists to teach | 400-700 words, with an example and exceptions |
| **Landmark topic** | A defining idea of the discipline | 800-1,500 words, with history, worked example, subsections, and moderate citation |

**Other proportions**

- **Paragraphs:** one central idea each, 4-10 lines. Write so that every paragraph can be summarised in a single line, because the side column will carry that summary.
- **Sections:** 3-6 per chapter.
- **Chapters:** about 8,000-12,000 words, or roughly 15-20 A4 pages at this density.
- **Opening puzzle:** about half to one page.

---

### 6. Examples: Two Tracks

**Track A: The running business.** The student "builds" one business across the book. Present it as a **documented case file**, not a story: dates, figures, decisions, and ledger entries, with no dialogue, invented characters' feelings, or narrative colour. It should grow in an order that matches the subjects:

- Business basics: choosing an idea and structure.
- Management: organising people and work.
- Accounting: recording transactions and preparing statements.
- Micro-economics: pricing, costs, demand, competition.
- Finance: funding, investment decisions, risk.

Label it clearly as **illustrative**, so no reader mistakes it for a real company.

**Track B: Real historical cases.** Use real, dated, verified events to show an idea at work (for example, the origins of double-entry bookkeeping, or early ideas of scientific management). Keep them short, factual, and attributed.

**Rules for both**

- Never invent history. If a date, figure, or quote cannot be verified, leave it out.
- State which country's rules apply when laws, tax, or standards differ by place (for example, accounting standards).
- Real company figures go out of date; prefer historical cases with settled facts, and date any current figures.

---

### 7. Numbers and Calculations

Students must be able to do this by hand, in exams. Never underestimate them and never skip a step.

**Every formula or calculation gets a worked example** laid out in the same order every time:

1. **Given.** List the data.
2. **Find.** State what is asked.
3. **Formula.** Write it in words, then in symbols.
4. **Steps.** Show every line of arithmetic, including units.
5. **Answer.** State it in a sentence.
6. **Check.** Show a quick test that the answer is sensible.

**Progression**

- First example: small, clean numbers, so the method is the only thing to learn.
- Second example: slightly messier, realistic numbers.
- Then a note on **common slips** (wrong sign, forgotten units, mixed-up periods).
- Practice problems close the chapter.

Explain where a formula comes from in a line or two when it helps, but full derivations are for landmark formulas only.

---

### 8. Referencing

- **Default: light.** Name the thinker and year in the text (for example, "Fayol, 1916") and list a few sources as further reading.
- **Defining topics: moderate.** Cite the founder or landmark work by name, with a short note on why it mattered, in a dedicated **Sources** section at the end of the chapter.
- **Clarifications and side points** go in footnotes.
- **One consolidated reading list** goes at the back of the book.
- Do not quote long passages from other works; paraphrase and credit.

---

### 9. Every Chapter Has the Same Shape

*(Written as tagged text; see Part V.)*

1. **Chapter opener** (full-page design from the visual guide).
2. **The opening puzzle:** a question or situation that makes the chapter necessary.
3. **Sections** built from concepts, each following the layered spine.
4. **A worked case** from the running business.
5. **The closing pack**, always in this order:
   - **Summary:** a few lines.
   - **Think it through:** a short problem or case.
   - **Where people go wrong:** common misunderstandings, stated and corrected.
   - **In history:** a true account of how this idea solved or saved something significant.
   - **Sources:** only for defining topics.
6. **Review questions** with short answers collected at the back of the book.

**Cross-references:** business subjects interlock (a cost in accounting is a cost in economics). When an idea appears in another chapter, point to it in the side column or a footnote.

---

### 10. Writing Checklist for Each Section

- Does it open with a question or an example before the rule?
- Is every term defined before it is used, and marked in bold once?
- Is each paragraph about one idea, summarisable in a line?
- Does every concept reach its exceptions, not only its rule?
- Is each explanation at least three full lines, and long enough to feel unhurried?
- Is every calculation worked in full, in the standard order?
- Is every historical claim verified?
- Would a student with no prior knowledge follow each step without guessing?

---

### 11. Settled Choices

- **Running case:** a bakery, shown as a documented case file.
- **Default standards and currency:** Bangladesh, taka (Tk); other systems noted only where they differ.
- **Review answers:** at the back of the book.

## Part III: Beginner Guide

*An extension of the Intellectual Guide. Everything there still applies; this guide adds extra care for absolute beginners. Field: Business, Management, Accounting, Micro-economics, Finance.*

---

### 1. Who the Reader Is

- A first-year student with **no prior knowledge** of business subjects. Every business term is new.
- **Comfortable with arithmetic and basic algebra**, so maths is not the barrier; unfamiliar vocabulary and unfamiliar ideas are.
- **English is a second language**, fluent in everyday communication. Technical business words are new, but they need **a simple definition in English, not a translation**.
- Intelligent and motivated. They are beginners in the subject, not in thinking.

**The guiding rule:** never assume the word, never assume the idea, never assume the reader is slow.

---

### 2. Language for a Second-Language Reader

**Sentences**

- For new or complex ideas, average **12-18 words** (shorter than the 18-22 in the main guide). One idea per sentence when defining.
- Keep the subject and verb close together. Avoid long stacks of nouns ("employee productivity performance measurement system").
- Make pronouns clear. If "it" could mean two things, repeat the noun.
- Prefer the active voice and everyday words. Choose the plain word over the grand one when both are correct.

**Avoid**

- Idioms and figures of speech that do not translate ("ballpark figure," "back to square one").
- Phrasal verbs where a single clear verb exists ("carry out" becomes "perform," "set up" becomes "establish," used consistently).
- Hedging stacks ("it could perhaps be argued that...").
- Words that dismiss difficulty: *simply, just, obviously, clearly, of course, as everyone knows.*

**One term, one meaning, one word.** Business English often has several words for the same thing (*revenue, sales, turnover*). Introduce the equivalents once, in a single sentence, then choose one word and keep to it. Never vary a term for style.

---

### 3. Defining New Terms

A new term appears **in bold** (plain bold, not italic), and its definition follows at once. Use this pattern:

1. **The term**, in bold.
2. **"means"** plus a **plain definition** of no more than about 20 words.
3. **A tiny example** in the next sentence.
4. **A side-column note** repeating the definition in one line.
5. **A glossary entry** at the back with the fuller definition and the chapter of first use.

**Rules for definitions**

- Use words **simpler than the term** being defined.
- Never define a term with another technical term the reader has not met. If you must use one, define it first.
- Never define in a circle ("a *liability* is something that creates a liability").
- No translations. Clarify with simple English, an example, or a short comparison.

**Words with two meanings (rare but important).** Some everyday English words carry a special business meaning: *account, capital, stock, interest, margin, cost, value, current, goods, balance.* When one first appears, add a short **"Word in use"** note in the side column:

> *Account. In daily life, a record of money in a bank. In accounting, a named record of one kind of item, such as Cash or Sales.*

Use these notes rarely and only where confusion is likely.

---

### 4. Pace: Two Speeds

#### Standard pace (most of the book)

- Introduce new ideas in **small groups** (two or three per section), never a flood.
- End each section with a **"Before moving on"** recap of 2-3 lines.
- Follow the layered spine: idea, example, rule, exceptions.

#### Slow pace (complex ideas and absolute firsts)

Switch to slow pace when a concept is **both new and abstract**, has **more than three moving parts**, or **depends on an earlier idea** that may not have stuck. Examples: opportunity cost, double-entry, accruals, marginal analysis, elasticity, the time value of money.

In slow pace:

1. **One idea at a time.** Finish one before starting the next.
2. **Everyday bridge first.** Begin with a situation from ordinary life (a household budget, a market stall, a part-time job) before the business version.
3. **Two forms of the same idea.** Give it in words, then in a simple diagram or a tiny numerical example.
4. **Smallest possible numbers** in the first example.
5. **Recap after each idea**, not just at the end of the section.
6. **A "You should now be able to say..." line** at the end: one sentence the reader can test themselves against.
7. A side-column flag (for example, *Go slowly here*) so the reader knows this passage deserves care.

Slow pace may use the upper end of the length tier. A concept that is new to the reader moves **up one tier** in length, with the three-line floor still applying to the smallest items.

---

### 5. Ordering: Nothing Before Its Time

- **Never use a term before it is introduced.** If a term must appear early, give a one-line preview and point to the section where it is taught.
- Open each chapter with a **"You will need"** note listing the earlier ideas it relies on, with page references.
- Sequence ideas by **dependency**: build each on what came before.
- Start from the reader's **own experience** (spending, saving, buying, selling) and move to business. The everyday bridge comes first, and the business case confirms it.
- The first three chapters are the **slowest** of the book. Their job is to teach the reader how to read the book as well as the subject.

---

### 6. Mathematics for This Reader

Readers are comfortable with arithmetic and basic algebra, so no refresher chapter is needed. Still:

- Follow the standard worked-example order (Given, Find, Formula, Steps, Answer, Check), showing every step, because business formulas combine familiar arithmetic in unfamiliar ways.
- **Write every formula in words first**, then in symbols, and say what each symbol stands for.
- The first time a chart appears, **say how to read it**: what the axes show, what a point means.
- Provide a short **"Maths you will use"** appendix of one or two pages: percentages and percentage change, ratios, averages, rearranging an equation, rounding, reading a graph. It is a reference, not a lesson.
- Keep early-chapter figures **small and round**; let them get realistic as confidence grows.

---

### 7. Repetition Without Boredom

Beginners need an idea to return several times in different forms. Build this in:

1. The idea appears in the text.
2. It appears in the **side-column note**.
3. It returns in the **"Before moving on"** recap.
4. It appears in the **chapter summary** and **review questions**.
5. It comes back in **later chapters** as a short "recall" note in the side column ("Recall: opportunity cost, page 34").

Place one or two **"Pause and check"** questions after slow passages so the reader tests understanding before moving on; put the answers in the side column or at the back.

---

### 8. Tone for Beginners

- **Encouraging without being patronising.** Treat confusion as normal and explainable.
- Be honest about difficulty, sparingly: *"Many students find this step confusing, because..."* and then remove the confusion.
- Never imply that the reader should already know something.
- Unfamiliar names from history (people, places, companies) get **one line of context**: who, when, where.
- Keep the dignified Victorian character of the book. Clear is not the same as casual.

---

### 9. Visual Support (Within the Visual Guide)

- A **simple diagram for each abstract idea**, in the engraving-style line art from the visual guide.
- Labels in plain words, not abbreviations, at first use.
- Tables show a few rows at a time, and the text explains how to read a row.
- A one-page **"How to read this book"** opening (in the "To the Reader" note) shows a sample page: where the side notes are, what bold type means, how footnotes work.

---

### 10. Beginner Checklist for Each Section

- Does any term appear before it is defined or previewed?
- Is each new term in bold, defined in about 20 words with simpler words, and followed by an example?
- Is there a side-column line repeating it?
- Are sentences short enough for the idea (12-18 words for new material)?
- Are there idioms, phrasal verbs, or words that dismiss difficulty?
- Is one word used for one concept throughout?
- If the idea is new and abstract, is it in slow pace, with an everyday bridge?
- Does the section end with a recap, and does a "You should now be able to say" line close slow passages?
- Does every numerical example show every step, with words before symbols?
- Would a reader with no business background follow each step without guessing?

---

### 11. Settled Choices

- **"Maths you will use" appendix:** at the back of the book.
- **"Pause and check" answers:** at the back of the book (the side column is too narrow for them).
- **"Word in use" notes:** at most three per chapter.

## Part IV: Visual Guide

*Reference for layout, typography, and print. Model: the page of Darwin's* On the Origin of Species *(1859). Audience: first-year university students.*

---

### 1. The Look in One Paragraph

A dense, dignified, Victorian-style academic book on A4, printed in near-black ink on warm cream uncoated paper, bound in burgundy cloth with gold lettering. Pages feel packed with knowledge: justified text with hyphenation, a narrow side column of notes, footnotes, running headers, and small flourishes between sections. No colour anywhere inside. Hierarchy is carried by weight, italics, small capitals, and rules.

---

### 2. Page Format

| Item | Specification |
| --- | --- |
| Trim size | A4 (210 × 297 mm) portrait |
| Bleed | 3 mm (needed only for cover and chapter-opener art that touches the edge) |
| Margins | Top 20 mm, bottom 22 mm, inner (gutter) 25 mm, outer 15 mm |
| Main text column | About 120 mm wide |
| Gap | 8 mm |
| Side column | About 42 mm wide, on the **outer** side (right on right-hand pages, left on left-hand pages) |
| Lines per page | About 50 |
| Chapter start | Always on a right-hand page; leave the left page blank if needed |

**Why this works:** A4 is wide, so full-width text would run past 100 characters per line and tire the eye. The side column uses the extra width for marginal notes and keeps the main line at about 65-70 characters.

---

### 3. Typefaces

All free and open-licence (Google Fonts), so you can embed them in print files without cost.

| Role | Typeface | Notes |
| --- | --- | --- |
| Body text | **Libre Caslon Text** | Sturdy, slightly full, very readable; closest free match to "old but readable." Fallback: EB Garamond (lighter, more delicate) |
| Headings | Libre Caslon Text **Bold**, capitals, letterspaced | Gives a full-bodied Victorian feel |
| Chapter titles | **IM Fell English** (SC for small capitals) | Authentic old-press character for the mood-setting display lines |
| Mood line and description | IM Fell English *Italic* |  |
| Side notes and footnotes | Libre Caslon Text, smaller |  |
| Cover title | Libre Caslon Display or IM Fell English, capitals, widely spaced | Gold foil |

**Rule:** Use only these families. Variety comes from weight, italic, and small capitals, never from extra fonts.

---

### 4. Text Setting

| Element | Specification |
| --- | --- |
| Body size | 10.5 pt on 14 pt leading |
| Alignment | Justified |
| Hyphenation | On. At least 3 letters before and after the break; no more than 2 hyphens in a row |
| Paragraphs | First-line indent of about 4.5 mm, **no space between paragraphs** |
| After a heading | First paragraph has no indent |
| Widows and orphans | Never fewer than 2 lines at the top or bottom of a page |
| Word spacing | Tight and even; avoid rivers of white space (adjust hyphenation, not letter-spacing) |
| Quotations | Longer quotes indented on both sides, 9.5 pt, no quotation marks |

---

### 5. Headings (Hierarchy by Weight, No Colour)

1. **Chapter title.** Full-page opener (see section 6).
2. **Section heading (level 1).** Bold capitals, 11 pt, letterspaced, centred, with a thin rule above and below. About 14 pt of space before, 8 pt after.
3. **Subsection heading (level 2).** Bold small capitals, left-aligned, on its own line.
4. **Minor heading (level 3).** *Italic*, regular weight, on its own line.
5. **Run-in heading (level 4, optional).** Small capitals at the start of the paragraph, followed by a full stop.

Sections are numbered in the contents only if you wish ("Section 1.2"). Do not number more than two levels.

---

### 6. The Chapter Opener (Full Page)

From top to bottom on one page:

1. Thin double-line frame around an **engraved illustration**, occupying roughly the upper half. Choose classic public-domain plates (Biodiversity Heritage Library, Internet Archive book images, Wikimedia Commons).
2. Small capitals, widely spaced: **CHAPTER THE FIRST**
3. **Chapter title** in IM Fell English, about 28 pt, centred.
4. A **mood line** in italic beneath it (one short phrase that sets the tone, for example a question or an image).
5. A small ornament or thin rule.
6. A **brief description** of the chapter: 3-4 lines, centred, in 10 pt italic, narrow measure.
7. Page number small at the foot. No running header on this page.

**Paragraphs always open normally.** There is no drop cap, no enlarged first letter, and no special styling on any paragraph, including the first paragraph after the chapter opener. The only difference is that a paragraph following a heading or opener has no first-line indent. This is a settled decision: the chapter's first paragraph begins exactly like every other.

---

### 7. Page Furniture

- **Running headers.** Left-hand page: the book title in small capitals. Right-hand page: the chapter title in small capitals. A thin rule sits below, and the page number is at the outer top corner.
- **Page numbers.** On every page. Chapter openers carry the number small at the bottom centre. Front matter uses lowercase Roman numerals (i, ii, iii); the main book uses Arabic numerals starting at 1.
- **Flourishes.** A centred ornament (❦ or ⁂) between major sections; a short centred thin rule for minor breaks. Keep to one or two ornament styles throughout.
- **Footnotes.** 8.5 pt on 10.5 pt leading, set at the foot of the page beneath a short thin rule (about 25 mm), numbered in order within each chapter.
- **Marginal notes (side column).** Two kinds, always distinguishable by style:
  - *Paragraph summaries:* short, one or two lines, in *italic* 8.5 pt.
  - **Key-term notes:** the term in **bold**, followed by a one-line plain definition in roman type.

Side notes align with the top line of the paragraph they belong to. If two notes collide, the second moves down; never cut a note short.

---

### 8. Marking Key Terms (for Beginners)

1. **First appearance in the text:** **bold** (plain bold, not italic).
2. **Side column:** a brief key-term note with a plain one-line definition.
3. **Back of the book:** a fuller glossary with longer definitions and the chapter where the term first appears.
4. After the first appearance, the term is set in ordinary type.
5. Bold is reserved for key terms at their first appearance and is never used for ordinary emphasis. Italics are used for emphasis, foreign words, and titles of works, so the two never get confused.

---

### 9. Figures, Tables, and Key-Term Boxes

Restrained and used only where they help.

- **Figures.** Line-engraving style drawings or simple line diagrams, black only. Caption beneath in 9 pt italic, preceded by **Fig. 1.** in small capitals. Number figures continuously through the book, or by chapter (Fig. 3.2), but keep one system.
- **Tables.** Horizontal rules only: one above, one below, and one under the column headings. No vertical lines, no shading. Caption above in small capitals.
- **Definition boxes.** Thin double-line border, no fill, a small-capitals label (DEFINITION or IN SHORT) at the top. Use sparingly, at most once or twice per chapter.
- **Wide figures.** May span the main column and side column together; never overlap the margin.

---

### 10. Front and Back Matter

**Front matter:** half-title, title page, copyright page, (optional dedication), contents, a short **"To the Reader"** note explaining how to read the side column, footnotes, and bold key terms, then preface.

**Contents page:** chapter titles in small capitals, dot leaders to page numbers, chapter numbers in Roman numerals.

**Back matter:** glossary, further reading, notes on sources, index.

---

### 11. Colour, Paper, and Ink

| Item | Specification |
| --- | --- |
| Ink | 100% black (K only) for all text and line art. No colour inside the book |
| Paper | Natural cream or ivory **uncoated** stock, about 90-100 gsm, warm (sometimes called "cream," "vanilla," or "book wove"). Avoid bright white and avoid glossy |
| Aged look | Comes from the paper stock itself, with clean pages. No printed stains or textures |
| Opacity | Choose a paper with good opacity so text does not show through on dense pages |

Always order a **sample proof** on your chosen stock before the full print run.

---

### 12. The Cover

- **Binding:** hardback, case-bound, with sewn (not glued) signatures so a thick A4 book opens flat and lasts.
- **Cloth:** burgundy book cloth, textured.
- **Front:** title in **gold foil**, capitals, widely spaced in a classic serif; a thin double-line border stamped in gold or blind-embossed; author name smaller beneath.
- **Spine:** title and author in gold, with thin gold rules near the top and bottom.
- **Extras (optional):** cream or gold headbands, a burgundy or gold ribbon marker, plain cream or marbled endpapers.

---

### 13. Production Checklist

1. Build the master pages first: margins, side column, running headers, page numbers.
2. Set up paragraph styles for each element above before writing pages.
3. Build the pages with the build script (Part V), which applies this guide's page, type and furniture rules. A layout tool (Affinity Publisher, InDesign, or LaTeX with a sidenotes package) is the fallback for manual finishing.
4. Export a print PDF (PDF/X) with fonts embedded and bleed included.
5. Check for widows, orphans, bad hyphenation, and side-note collisions on every page.
6. Print a proof copy on the intended paper before approving the run.

- **Body typeface:** Libre Caslon Text; EB Garamond is not used.
- **Chapter art:** one illustration per chapter; the placeholder engraving stands in until real plates are supplied (`:plate`).
- **Figure numbering:** continuous through the book (Fig. 14); the build script counts them (`--fig-start` continues a count).

## Part V: Token-Saving Guide

*It changes only **what is written** and **how much is re-sent**. Parts II to IV still govern content, language and look. A build script turns the tagged text into the finished A4 PDF, so no layout code is ever written in a chapter chat.*

---

### 1. Rules for the Assistant

1. **Write at least one full chapter per chat.** A second chapter is allowed only if the first came out short and budget clearly remains. If one chapter cannot fit, stop at the end of a section, write `RESUME: <next section>` and say so in one line.
2. **Output tagged text only** (section 2). Never write HTML, CSS, SVG or page layout.
3. **Do not re-read or restate Parts I to IV.** Use the style card (section 3) and the blueprint entry.
4. **Never reprint a file.** Change state files with small edits or appends.
5. **No self-review prose.** Check silently (section 4); report failures only. Skip checks when the draft is clearly clean.
6. **No preamble, no explanations of choices.** Begin with the chapter.
7. **Ending (section 5) is short.** Extra detail only if a major problem arose.

---

### 2. Markup Specification

One chapter is one `.md` file. Blank lines separate paragraphs. A line ending without a blank line continues the paragraph.

| Write | Meaning |
| --- | --- |
| `:chapter VII \| The Partnership` | Chapter number and title (first line) |
| `:mood <one line>` | Italic line under the title |
| `:desc <3-4 lines>` | Description on the opener page |
| `## Heading` | Section heading (level 1) |
| `### Heading` | Subsection heading (level 2) |
| `> one-line summary` | Side note summarising the **next** paragraph |
| `@ Term \| one-line definition` | Key-term side note for the next paragraph |
| `@! Go slowly here.` | Slow-pace flag in the side column |
| `**term**` | Bold, first appearance of a key term only |
| `*word*` | Italic for emphasis, foreign words, titles |
| `^1` in text, `^1: note` on its own line | Footnote reference and its text (any position; numbered in chapter order) |
| `* * *` | Ornament between major parts |
| `:case <paragraph>` | A case-file paragraph (the text begins with *Case file, illustrative.*) |
| `:table Caption` then lines `\| Head \| Head \|` and `\| cell \| cell \|` | Table: first line is the header row; horizontal rules only; introduce it in words first |
| `:fig Caption \| file.svg` | Figure from an uploaded svg, png or jpg; numbered continuously (Fig. 1, 2, ...) |
| `:box LABEL` then one paragraph | Definition box (label such as IN SHORT); once or twice per chapter |
| `:plate file \| caption` | Chapter-opener engraving (optional; a placeholder is used if absent) |
| `:todo <note>` | Reminder to yourself; the validator lists it |

**Placement:** side-note lines (`>`, `@`, `@!`) go directly above the paragraph they belong to, in the order they should appear. Every paragraph gets a `>` summary; key-term notes are added where a term is defined.

### 3. Style Card (the whole voice in brief)

**Reader:** first-year, no business background, English as a second language, intelligent. Never assume the word, the idea, or that the reader is slow.

**Registers:** *Storyteller* opens a new idea with a puzzle or question. *Plain authority* states definitions and rules in short, exact sentences. *Patient tutor* (we, you) walks through procedures. *Measured professor* frames and judges, dignified and slightly formal.

**Sentences:** 12-18 words for new material, 18-22 elsewhere; one idea per sentence when defining; active voice; no idioms or phrasal verbs; never *simply, just, obviously, clearly*. One term, one word, used the same way throughout.

**Definitions:** bold at first use; "X means / is..." in about 20 words, using simpler words than the term; a tiny example next; the same definition in the side note. No circular or translated definitions.

**Spine:** idea, example, rule, exceptions. Open with a puzzle (half to one page). New and abstract ideas go **slow**: everyday bridge first, smallest numbers, one idea at a time, recap, then a "You should now be able to say..." line.

**Length:** minor term 3-8 lines; standard 150-300 words; core 400-700; landmark 800-1,500. Paragraphs 4-10 lines, one idea each.

**Chapter shape:** opener data (`:chapter`, `:mood`, `:desc`), opening puzzle, 3-6 sections, worked case, then in order: Summary, Think it through, Where people go wrong, In history, Sources (defining topics only), review questions.

**Descriptive courses:** worked case (Situation, Question, Reasoning, Conclusion, Check). Comparison tables are introduced in words first.

**Sample (the voice in eight lines):**

```
## The Idea of Partnership

> Two people, each lacking something, decide to join forces.

Imagine that two friends, one skilled at baking and the other at selling, decide to open a small bakery together. Neither can afford the oven alone, and neither can run the shop alone. Before a single sack of flour is ordered, one question stands between them and their business: who owns what, and who answers for what?

@ Partnership | Two or more people running a business together and sharing its profits.

The law gives the name **partnership** to such an arrangement. A partnership is a business owned by two or more people who have agreed to run it together and to share its profits.^1
```

### 4. Silent Checks (report failures only)

Check these without writing about them:

1. No objectives, topics, exam years, marks, frequencies or question wording from the course file appear. *(Overrides everything.)*
2. Every date, name, figure and legal point is verified; unverifiable items are cut or listed under "verify" at the end.
3. Every term is defined before use, bold only at first use.
4. Every paragraph has a `>` summary; every footnote reference has its text.

`python3 build.py *.md --check` (no PDF, almost no cost) flags most of items 1, 3 and 4: course-file wording, terms not in bold in their paragraph, repeated bold, paragraphs without a summary, unmatched footnotes, unknown tags. Item 2 (facts) is for the assistant.

### 5. Chapter Ending (minimal)

After the chapter, write only:

- One line: chapter finished (or `RESUME:` point).
- **New:** the new terms and any new case-file facts, each as a short item, **only if** they are not already in the state file.
- **Verify:** facts needing a check, if any.
- One line asking to continue with the next chapter.

## Part VI: Planning Guide

*What goes in the book, and in what order. Turns the course file into a chapter blueprint. The course file (learning outcomes, topics, past questions) is private input used only here and in the checks; none of it appears in the book.*

### 1. Input

A course file as JSON, a spreadsheet, or pasted text: learning outcomes (objectives), each with its topics, and past questions with their sub-questions and, where known, marks, year and topic. Missing fields are acceptable.

### 2. The Steps

1. **Inventory.** List outcomes, topics and questions exactly as found. Change nothing.
2. **Flatten topics.** Make one list of unique topics. Merge duplicates; keep the link to the outcome in the working file only.
3. **Profile the questions.** For each, record its type (define, explain, compare, calculate, apply to a case, discuss), the skill it tests, marks and year if given, and repeated question families. Frequency and marks are recorded but **never change how large a topic is** in the book.
4. **Map questions to topics.** Trace each question to one or more topics. Log questions with no topic and topics with no questions; neither is dropped.
5. **Break topics into concepts.** A concept is one idea the reader must hold. List each concept's prerequisites.
6. **Draw the dependency map.** Order concepts by prerequisite. Decide what an absolute beginner must learn first (vocabulary, everyday bridges) and add it as foundation material, even if no topic names it.
7. **Form chapters and sections.** Group by teaching logic, so that ideas which explain each other sit together: 3-6 sections per chapter, about 8,000-12,000 words (Part II, section 5). Order chapters by dependency.
8. **Name and clean.** Give chapters and sections plain subject titles. Run the clean-out scan: no objective labels, exam years, marks, frequency remarks or copied question wording in any title, summary or note. Settle overlaps between chapters by one cross-reference, not by repetition.
9. **Write one blueprint entry per chapter:** title; purpose in one line; sections, each with its kind of topic and length tier (Part II); concepts and prerequisites; new terms; the chapter's step in the case file; the historical case (to be verified); cross-references; and a "You will need" list of earlier ideas.
10. **Plan examples and practice.** For each chapter, plan the example ladder: for calculation topics, clean numbers first, then messier ones; for descriptive topics, a familiar case, a reshaped case, a new setting, then a case combining earlier ideas. Build the end-of-chapter practice (review questions and "Think it through") from the question families, rewritten in new words with new data.
11. **Silent coverage check.** Confirm that every question tied to a chapter can be answered from it. Fix gaps by adding teaching content, never by quoting the question, and record them in the decision log.

> **Checkpoint 1** (Part I, Stage 3): the author reviews the blueprint before any drafting begins.

# ---------- hyphenation (Liang patterns from TeX's hyphen.tex; soft hyphens) ----------
_P = None
def _pat():
    global _P
    if _P is None:
        _P = {}
        try:
            t = open(glob.glob('/usr/share/texlive/texmf-dist/tex/generic/hyphen/hyphen.tex')[0], encoding='latin-1').read()
            i = t.index('\\patterns{'); j = t.index('}', i)

                for ch in p:
                    if ch.isdigit(): V[-1] = int(ch)
                    else: L += ch; V.append(0)
                _P[L] = V
        except Exception: print("NOTE: no hyphenation patterns found; text will not be hyphenated")
    return _P
def hy(w):
    P = _pat()
    if not P: return w
    x = '.' + w + '.'; v = [0] * (len(x) + 1)

        for j in range(i + 1, min(len(x), i + 9) + 1):

                    if v[i + k] < a: v[i + k] = a

def hyph(s):
    return ''.join(g if g.startswith('<') else re.sub(r"(?<![&#\w])[a-z]{7,}(?![;\w])", lambda m: hy(m[0]), g) for g in re.split(r'(<[^>]+>)', s))

def inline(s):

    s = re.sub(r"\*\*(.+?)\*\*", r"<b>\1</b>", s)
    s = re.sub(r"\*(.+?)\*", r"<i>\1</i>", s)

            st['bold'].add(b)
        st['pend'] = []; st['words'] += len(t.split())

        st['cls'] = ''; st['brk'] = False

        rows.append(dict(t='x', h=h, html=f'<div class="row"><div class="side">{sd}</div><div class="main">{inner}</div></div>')); st['brk'] = True
    while i < len(L):

        if not s.strip(): flush(); continue

        flush()

        elif s.startswith('@ '):

        else: st['buf'].append(s)
    flush()
    used = {int(n) for r in rows for n in re.findall(r"<sup>(\d+)</sup>", r.get('text', '') + r.get('html', ''))}
    for n in used - set(fn): warn.append(f'footnote {n} cited but not defined')
    for n in set(fn) - used: warn.append(f'footnote {n} defined but never cited')
    if st['side']: warn.append('side notes with no paragraph after them')
    for k in ('chapter', 'mood', 'desc'):
        if k not in meta: warn.append(f'missing :{k}')
    return meta, rows, fn, terms, warn, st['fig'], st['words']

def fontcss(extra):
    dirs = [d for d in [extra, os.path.join(HERE, 'fonts'), '/mnt/user-data/uploads'] if d and os.path.isdir(d)]
    for d in dirs:
        for z in glob.glob(os.path.join(d, '*.zip')):
            try: zipfile.ZipFile(z).extractall(os.path.join(HERE, '_fonts'))
            except Exception: pass
    out, found = [], set()
    for d in dirs + [os.path.join(HERE, '_fonts')]:
        for f in glob.glob(os.path.join(d, '**', '*.[ot]tf'), recursive=True):
            n = os.path.basename(f).lower()
            fam = 'Libre Caslon Text' if 'caslon' in n else ('IM Fell English SC' if 'fellenglishsc' in n.replace(' ', '') or 'english-sc' in n else ('IM Fell English' if 'fell' in n else None))
            if not fam: continue
            w = '400 700' if '[' in n else ('700' if 'bold' in n else '400'); it = 'italic' if 'italic' in n else 'normal'
            found.add(fam); out.append(f"@font-face{{font-family:'{fam}';src:url('file://{f}');font-style:{it};font-weight:{w}}}")
    return '\n'.join(out), found
